# Платформа-агрегатор ИТ-вакансий с верифицированным профилем (хакатон, MVP)

Рабочее название: **IT-Talent Match** — платформа обратного подбора.

## Что это

Веб-сервис подбора ИТ-специалистов с **обратной механикой**: соискатели
автоматически распределяются по категориям (специализация × грейд) на основе
объективно подтверждаемого профиля (опрос + тест + достижения), а **работодатель
сам** находит нужную категорию и направляет приглашение с уровнем заработной
платы. Прямой отклик кандидата — дополнительный сценарий.

Дополнительно реализован **ИИ-слой на локальной открытой модели** (Ollama, любая
совместимая модель): автоматизация рутинных текстовых операций и семантическое
сопоставление. Персональные данные при этом не покидают контур, а при отсутствии
модели платформа переходит в демо-режим и продолжает работать.

## Быстрый старт

### Вариант 1 — весь стек в Docker

```bash
cp .env.example .env
docker compose up -d --build      # миграции БД применяются автоматически при старте API
docker compose ps                 # 4 сервиса в статусе Up (healthy)
docker compose exec -T backend python scripts/seed_demo.py   # демо-данные
```

> Схему базы создаёт сам контейнер API (`alembic upgrade head` перед запуском),
> поэтому отдельный шаг с миграциями не нужен — ни на чистой машине, ни после
> `docker compose down -v`.

- SPA: http://localhost:8080
- API и Swagger: http://localhost:8000/docs
- Готовность: http://localhost:8000/api/v1/health/ready

Пошаговая инструкция для неспециалиста (что установить, что нажимать в демонстрации,
что делать при ошибках) — `docs/lean-canvas.html`, раздел 16.

### Вариант 2 — локальный запуск

Backend (нужен Python 3.12; удобнее через `uv`):

```bash
cd backend
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt -r requirements-dev.txt
env -u PYTHONPATH .venv/bin/python -m uvicorn app.main:app --reload --port 8000
```

> `env -u PYTHONPATH` нужен, если в окружении задан `PYTHONPATH` — иначе в
> `sys.path` попадают чужие site-packages и импорты разрешаются неверно.

Frontend:

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173 (проксирует /api на :8000)
```

Проверки:

```bash
cd backend && env -u PYTHONPATH .venv/bin/python -m pytest -q   # 264 теста
bash ../scripts/reset-demo.sh                                   # чистое состояние для демонстрации
bash ../scripts/smoke-api.sh                                    # smoke-проверка API
cd frontend && npm run build                                    # сборка SPA + строгая типизация
```

## ИИ-слой: как включить и как выключить

Модель не обязательна для работы платформы. Управление — переменными окружения
(`.env`):

| Переменная | Значения | Назначение |
|---|---|---|
| `LLM_PROVIDER` | `auto` (по умолчанию) \| `ollama` \| `mock` | `auto` — реальная модель с откатом в демо-режим; `ollama` — только реальная модель; `mock` — всегда демо-данные (автотесты, оффлайн) |
| `OLLAMA_BASE_URL` | по умолчанию `http://host.docker.internal:11434` | адрес Ollama с хоста |
| `OLLAMA_MODEL` | пусто = автоподбор | конкретная модель, например `gemma3:12b` |
| `OLLAMA_EMBED_MODEL` | пусто = автоподбор | модель эмбеддингов для семантического сопоставления |
| `LLM_THINK` | `false` (по умолчанию) | режим рассуждений: на коротких задачах замедляет ответ в разы |
| `SEMANTIC_MATCH_ENABLED` | `true` \| `false` | учитывать семантическое соответствие в подборе |

Состояние слоя видно в интерфейсе (значок «ИИ: локальная модель» / «ИИ: демо-режим»)
и по эндпоинту `/api/v1/ai/status`. Проверка сквозным сценарием:

```bash
bash scripts/smoke-ai.sh
```

Подключение любой другой открытой модели — это настройка Ollama, а не правка кода:
провайдер выбирается абстракцией. Подробности и замеры — `docs/06-ai.md`.

## Качество кода

Рефакторинг выполнен по всему проекту; проверки воспроизводимы:

```bash
cd backend
env -u PYTHONPATH .venv/bin/ruff check .      # линтер: без замечаний
env -u PYTHONPATH .venv/bin/ruff format --check .
env -u PYTHONPATH .venv/bin/vulture app --min-confidence 80   # мёртвый код: чисто
env -u PYTHONPATH .venv/bin/python -m pytest -q               # 253 теста
env -u PYTHONPATH .venv/bin/python -m pytest -q --cov=app --cov-report=term-missing  # покрытие 97%
cd ../frontend && npm run build               # включает строгую проверку типов tsc
cd .. && bash scripts/smoke-ai.sh             # ИИ: источник ответа и деградация
```

Принципы, зафиксированные в ходе рефакторинга:

- **Зависимости отражают реальность.** Перечень в `requirements.txt` сверен с
  фактическими импортами: неиспользуемые библиотеки удалены, `httpx` оставлен
  **в рантайме** (нужен для Ollama и проверки OIDC-токенов Keycloak), инструменты
  качества (`ruff`, `vulture`) зафиксированы по версиям.
- **Нет мёртвого кода.** Общие части интерфейса вынесены в переиспользуемые
  компоненты (`CandidateRow`, `InvitePanel`), неиспользуемые методы API-клиента
  подключены к интерфейсу (поиск по банку, история подборок, ИИ-функции), справочник
  грейдов берётся из API, а не дублируется в разметке. Все 51 функция API-клиента
  вызываются из интерфейса.
- **Действие соответствует подписи.** Уточнение подборки действительно создаёт новую
  версию (`POST /selections/{id}/refine`) с сохранением прежней, а не перезагружает
  экран; приглашение помечается просмотренным при открытии вкладки; переключатели
  приватности сохраняются на сервере, а не только в состоянии формы.
- **Измеритель проверяется наравне с кодом.** Покрытие считается ядром
  `sysmon` (`[tool.coverage.run] core = "sysmon"`): штатный C-трассировщик
  в этом окружении занижает результат на одном и том же прогоне (42% против
  90% на одном файле). Без этой настройки метрика вводит в заблуждение.
- **Числа в документации сверяются с фактом.** Количество методов API, тестов,
  миграций и источников берётся из работающей системы, а не из ранних заметок.

## Лицензии и данные

Открытый исходный код без обфускации; зависимости — с разрешительными лицензиями
(pypdf и reportlab вместо PyMuPDF под AGPL). Персональные данные обрабатываются
в контуре решения: Argon2id для паролей, JWT access/refresh, RBAC по ролям,
раздельные согласия на обработку и на публикацию данных; локальная модель исключает
передачу резюме во внешние сервисы.
