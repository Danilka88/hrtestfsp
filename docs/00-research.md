# 00. Исследование и Lean Canvas

Документ фиксирует результат исследования предметной области, рынка и лучших
практик, на которых строится решение. Все утверждения снабжены ссылками на
источники (см. раздел «Источники»).

---

## 1. Рынок и проблема (РФ, 2025–2026)

- За год рынок вакансий в РФ просел **на 25%**, в ИТ — **около 20%**, при этом
  число активных резюме выросло **более чем на четверть** [13].
- По данным hh.ru, число резюме в категории «Информационные технологии» растёт
  на **20–30% ежемесячно** год к году, тогда как количество вакансий сократилось
  **на 11–36%** [12].
- Работодатель тонет в **нерелевантных откликах** (особенно от начинающих), при
  этом испытывает **дефицит опытных профи**, которые не сидят на классических
  job-сайтах [12].

**Вывод.** Ниша — «обратный» подбор с объективной верификацией квалификации, а не
ещё один агрегатор вакансий.

## 2. Референсные механики («работа находит человека»)

- **LHH (Lee Hecht Harrison)** — модель **Active Placement**: переход от
  «человек ищет работу» к **«работа находит человека»**; талант продвигается
  напрямую работодателям. Только **15%** находят работу через job-борды, **85%** —
  через сети [1][2].
- **Hired / Vettery** — маркетплейс, где работодатель сам направляет
  **interview request** прямо кандидату; доски вакансий не показываются [3][5].
- **Reverse job board** — кандидат публикует профиль, работодатель просматривает
  и платит за контакт [4]. **Underdog.io**: одобренные кандидаты «выходят в лайв»
  партиями [5].

**Вывод.** Механика подтверждена рынком, но прямого аналога в РФ с верификацией
квалификации через тест и достижения нет — это и есть дифференциатор.

## 3. Механика тестирования: что говорит наука

Противоречие «уникальные задания у каждого ↔ сопоставимая сложность» в
психометрике решается комбинацией подходов:

- **Computerized Adaptive Testing (CAT) + Item Response Theory (IRT)** — задания
  калибруются по сложности, каждому выдаётся набор, дающий точную оценку за
  меньшее число вопросов [6][7].
- **On-the-fly item generation** — генерация заданий «на лету» из
  параметрических шаблонов даёт **изоморфные по сложности** формы [7].
- **Item exposure control** — лимит показов задания, ротация, взвешенный отбор;
  защита от «расхождения заданий по рынку» [9].
- **Детекция компрометации заданий** — по баллам и **времени ответа** в реальном
  времени выявляются «слитые» задания и кандидаты, отвечавшие по предзнанию [6].
- **ITC Guidelines on Security of Tests** — мониторинг регистраций, флаг аномалий
  по времени [8].
- **Прокторинг** доступен в РФ (Examus, ProctorEdu, StartExam) [25].
- **Антиплагиат кода** — сравнение по токенам/AST для задач с кодом [26].

## 4. Объяснимость ранжирования (XAI)

Требование «объяснимость выдачи» — рыночный стандарт: рубрика с критериями и
весами, **зафиксированная до просмотра пула**, **evidence-trail** под каждый
критерий, «missing information stays missing», аудит высоких/средних/низких
рангов [10][11].

## 5. Разбор резюме (NLP)

- Извлечение навыков из русскоязычных текстов: сравнение encoder-NER и LLM
  показало лучшую обобщаемость **LLM** на новых формулировках [22].
- Для семантического матчинга — русскоязычные эмбеддинги (**ruMTEB /
  ru-en-RoSBERTa**) [23].
- Для генерации/разбора доступна **GigaChat REST API** [24].

## 6. Практики хакатон-MVP

- **Demo-first**: победители строят демонстрационный путь, а не архитектуру;
  скоуп — «одна вещь хорошо», а не пять наполовину [18][19].
- Сначала проблема для жюри, потом технология; питч репетируется [18].

## 7. Холодный старт (two-sided marketplace)

Классическая проблема «курица-яйцо» [20]; сначала определить, supply- или
demand-constrained [21]. Для хакатона решается демо-данными и seed-скриптом.

## 8. Регуляторика и ориентиры стека

- **152-ФЗ**: с **1 сентября 2025** согласие на обработку ПДн — **отдельный
  документ**, не спрятанный в оферте [16].
- **Реестр отечественного ПО** — льготы (налог на прибыль 3%, НДС) [17].
- **Keycloak + Next.js/React + FastAPI** — проверенные блупринты (stateless,
  multi-tenant, RBAC) [15][30].

## 9. Выводы → рекомендуемые механики (ядро решения)

### 9.1 Механика тестирования — гибрид «генерация + калибровка»

1. **Параметрическая генерация** заданий из шаблонов (фабрики задач): уникальные
   варианты, эквивалентные по сложности [7].
2. **IRT-калибровка + адаптивная выдача**: сопоставимая оценка, короткий тест [6][7].
3. **Item exposure control + детекция компрометации**: ротация, лимит показов,
   аномалии по времени ответа [6][8][9].
4. **Антиплагиат кода** для задач с кодом [26].
5. **Скоринг по рубрике** → грейд, а не «верно/неверно» [28].

### 9.2 Механика подбора — обратная

- Работодатель описывает потребность → получает **подборку по категориям** и
  конкретных кандидатов.
- Ранжирование внутри категории: сила подтверждённого профиля (тест) → достижения
  ФСП → свежесть (регулярные задания).
- **Объяснимость** через рубрику с evidence-trail [10][11].
- Приглашение: **обязательно ЗП (диапазон)**, компания, описание предложения;
  **контакты скрыты** до принятия/отклика.
- **Фильтрация без потери подборки**: состояние подборки сохраняется.

### 9.3 Категоризация

Категория = **специализация × грейд**. Грейд — из теста; самооценка только
выбирает уровень тестирования. Смена грейда ограничена по времени [28].

### 9.4 Интеграция с реестром ФСП

Провайдер-адаптер (`FspProvider`) с реальной и mock-реализацией; обязательна
корректная обработка кандидата **без истории** [29].

### 9.5 Демо-режим

Всё внешнее (LLM, прокторинг, ФСП, email, storage) — за интерфейсом с
**mock-провайдером + seed-данными**. Демо воспроизводимо оффлайн [18][19].

## 10. Lean Canvas

| Блок | Содержание |
|---|---|
| **Problem** | ① Работодатель тратит дорогое время на вал нерелевантных откликов; нет объективного сигнала о практической компетентности. ② Кандидат откликается вслепую, без обратной связи; резюме не подтверждает навык. ③ ИТ-специфика (стек/грейд/роль/формат) не формализована на универсальных площадках. |
| **Customer Segments** | **Работодатели ИТ** (нанимающие менеджеры/HR); early adopter — компании, ищущие подтверждённо-квалифицированных и готовые платить. **Кандидаты ИТ** (junior→senior), особенно участники соревновательного движения. **Партнёр ФСП** — владелец объективных данных о достижениях. |
| **Unique Value Proposition** | «Работодатель находит **уже подтверждённую категорию** и сам приглашает — **с зарплатой сразу**, без вала резюме. Кандидат получает приглашения, а не откликается вслепую». Верификация = тест + достижения. |
| **Solution** | ① Обязательный путь: опрос → грейд → адаптивный тест → категория. ② Обратный подбор: подборка/поиск → приглашение с ЗП → раскрытие контактов по согласию. ③ Верифицированный профиль + регулярные короткие задания. |
| **Channels** | Прямые продажи в ИТ-компании; партнёрство с ФСП и сообществами; конференции/соревнования; Habr/Telegram; реферальная программа. |
| **Revenue Streams** | Подписка работодателя (SaaS); платный контакт/success-fee; премиум кандидата; партнёрство с ФСП. *(в MVP не реализуем — только модель)* |
| **Cost Structure** | Разработка и поддержка; инфраструктура (VPS, LLM API); модерация/антифрод; юридическое (152-ФЗ). |
| **Key Metrics** | Доля релевантных в топ-10; конверсия приглашение→принятие; время до первого приглашения; стабильность грейда при повторном тесте; дискриминативность заданий; active employers/candidates. |
| **Unfair Advantage** | Данные и бренд **ФСП**: объективные результаты соревнований как эксклюзивный сигнал, которого нет у универсальных площадок [29]. |
