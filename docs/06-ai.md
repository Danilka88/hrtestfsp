# 06. ИИ-слой: локальная модель, автоматизация и деградация

## 1. Зачем ИИ в этом продукте

Платформа работает **без ИИ**: кандидат заполняет профиль вручную, работодатель
описывает потребность сам, подбор и тестирование — детерминированные алгоритмы.
ИИ добавлен как **ускоритель рутинных действий**, а не как обязательная часть
сценария. Это принципиально: демонстрация не должна зависеть от того, есть ли
модель на машине проверяющего.

## 2. Почему локальная модель, а не внешний API

| Причина | Пояснение |
|---|---|
| **152-ФЗ** | Тексты резюме и профилей не покидают контур: нет передачи персональных данных третьим лицам |
| **Нет ключей и лимитов** | Демонстрация не зависит от баланса, квот и доступности внешнего сервиса |
| **Любая открытая модель** | Код не привязан к конкретной модели: имя задаётся настройкой, модель выбирается из уже скачанных |
| **Разрешительные лицензии** | Gemma 4 — Apache 2.0; Qwen — Apache 2.0; подходят также MIT-модели |

## 3. Как подключить модель

```bash
# 1) установить Ollama (macOS: brew install ollama; Linux/Windows: с сайта ollama.com)
# 2) скачать любую открытую модель
ollama pull gemma4:12b-mlx      # или gemma3:4b / qwen3:8b / llama3.1:8b …
# 3) запустить службу
ollama serve
# 4) указать модель в .env (пусто = выбрать автоматически из скачанных)
OLLAMA_MODEL=
```

**Автоподбор модели.** Если `OLLAMA_MODEL` пуст, провайдер опрашивает Ollama
(`/api/tags`) и выбирает первую доступную модель по порядку предпочтения:
`gemma4 → gemma3 → qwen3 → qwen2.5 → llama3 → mistral → phi → deepseek`.
Модели эмбеддингов, OCR и распознавания речи из выбора чата исключаются. Поэтому
на машине проверяющего подойдёт **любая** скачанная модель — код менять не нужно.

Проверено на локальной конфигурации: доступны `gemma4:e4b-mlx`, `gemma4:12b-mlx`,
`gemma4:26b-mlx`, `qwen3-embedding:0.6b`, `qwen3-vl:2b`, `deepseek-ocr`.

## 4. Режимы работы и деградация

Настройка `LLM_PROVIDER`:

| Значение | Поведение |
|---|---|
| `auto` (по умолчанию) | Пробуем локальную модель; при недоступности — детерминированные демо-данные |
| `ollama` | Только реальная модель: ошибка, если недоступна (для отладки) |
| `mock` | Только демо-данные, без обращений наружу (полностью офлайн) |

**Деградация видна пользователю.** Каждый ответ API содержит `degraded: bool` и
`provider`. Интерфейс показывает это явно: индикатор в шапке кабинета
(«ИИ: gemma4:e4b-mlx» или «ИИ: демо-режим»), пометка под сгенерированным текстом
и отдельный вид всплывающего уведомления. Пользователь не должен думать, что
видит работу модели, когда её нет.

Пример из практики: при остановленной Ollama те же шесть функций отвечают за
**11–17 мс** и помечают ответ `degraded=true`, а порядок релевантности в
семантическом сопоставлении сохраняется.

## 5. Что автоматизируется

| Функция | Эндпоинт | Роль | Что ускоряет |
|---|---|---|---|
| Разбор профиля и резюме | `POST /ai/profile/analyze` | кандидат | Извлекает стек, роли, стаж и подсказывает, что дополнить |
| Черновик описания потребности | `POST /ai/need/draft` | работодатель | Превращает короткую заметку в структурированную потребность |
| Черновик приглашения | `POST /ai/invitation/draft` | работодатель | Готовый текст предложения с условиями |
| Сопроводительное письмо | `POST /ai/cover-letter` | кандидат | Письмо под вакансию на основе реального пересечения стека |
| Объяснение попадания в подборку | `POST /ai/match/explain` | работодатель | Формулирует причину на основе сохранённых критериев |
| Заготовка короткого задания | `POST /ai/task/draft` | работодатель | Задание на 20 минут с критериями оценки |
| Семантическое сопоставление | `POST /ai/semantic/scores` | обе роли | Косинусная близость потребности и профилей |
| Состояние слоя | `GET /ai/status` | обе роли | Показывает активную модель и режим деградации |

**Ограничения соблюдаются осознанно:**
- ИИ не определяет грейд — его присваивает только тест (иначе обходится ядро №1);
- ИИ не выдумывает опыт: в сопроводительном письме используются только реально
  совпавшие технологии, а отсутствующие данные не додумываются;
- ИИ не влияет на ранжирование: веса рубрики фиксированы и объяснимы.

## 6. Особенности Gemma 4, найденные замерами

Замеры на Apple Silicon, модель `gemma4:e4b-mlx`:

| Наблюдение | Значение | Что сделано |
|---|---|---|
| Включённый reasoning замедляет короткие задачи | 9.8 с против **0.25 с** | `LLM_THINK=false` по умолчанию |
| Без `format=json` модель оборачивает JSON в ` ```json ` | ломает `json.loads` | Провайдер передаёт схему и снимает обёртку |
| Модель может не заполнить поле ответа | `specialization_code` отсутствовал | Ответ нормализуется к справочникам платформы |
| Структурированный вывод | Ollama гарантирует валидный JSON при `format` | Разбор не строится на регулярных выражениях |

**Замеренная задержка функций** (gemma4:e4b-mlx, прогрев выполнен): разбор
профиля 1.8 с, черновик потребности 2.1 с, черновик приглашения 2.1 с,
сопроводительное письмо 2.2 с, заготовка задания 6.1–6.8 с.

## 7. Эмбеддинги и семантическое сопоставление

`qwen3-embedding:0.6b` даёт векторы размерности 1024. Замер: близкий по смыслу
текст («Backend-разработчик Python FastAPI PostgreSQL» против «Python FastAPI
PostgreSQL разработчик») — косинус **0.92**, далёкий (против «Дизайнер интерфейсов
Figma») — **0.55**.

**Офлайн-режим.** Без модели эмбеддингов применяется хеширующий мешок слов
(feature hashing, 256 измерений): это честная **лексическая** близость, а не
нейросетевая. Совпавшие технологии сближают тексты, поэтому порядок релевантности
сохраняется — что и проверено в тестах.

Это закрывает пробел «нет ML/NLP в решении»: семантическое сопоставление
реализовано и работает на локальных эмбеддингах, а в офлайне деградирует
предсказуемо.
