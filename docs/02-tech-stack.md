# 02. Технологический стек

Перечень ниже **отражает то, что действительно используется в коде**, а не
планируемый стек. Проверяемость:

```bash
# 1) фактические версии в окружении
cd backend && env -u PYTHONPATH .venv/bin/python -c "import importlib.metadata as m; print(m.version('fastapi'))"
# 2) какие модули реально импортируются в app/ (AST-анализ)
# 3) линтер и поиск мёртвого кода
env -u PYTHONPATH .venv/bin/ruff check . && env -u PYTHONPATH .venv/bin/vulture app --min-confidence 80
```

Точные версии фиксируются в `backend/requirements.txt`,
`backend/requirements-dev.txt` и `frontend/package-lock.json`.

## 5. Внешние зависимости — за интерфейсами (mock-first)

| Интерфейс | Реальная реализация | Реализация по умолчанию (MVP) |
|---|---|---|
| `LLMProvider` | **Ollama**: любая открытая модель (Gemma 4 — Apache 2.0, Qwen, Llama, Mistral) | Детерминированные демо-данные при недоступной модели |
| `EmbeddingProvider` | **Ollama**: `qwen3-embedding` и аналоги | Хеширующий мешок слов (лексическая близость) |
| `AuthProvider` | **Keycloak** (OIDC: токены realm + проверка `id_token` по JWKS) | `LocalAuthProvider`: Argon2 + собственные JWT |
| `FspProvider` | Реестр ФСП | Синтетические достижения из seed |
| `EmailProvider` | SMTP | Логирование в консоль |
| `StorageProvider` | S3/MinIO | Локальный том |
| `ProctorProvider` | Внешний прокторинг | Заглушка «не подключено» |

**Правило:** любая внешняя зависимость имеет запасную реализацию, поэтому демо
воспроизводимо оффлайн и не зависит от доступности сторонних сервисов. Для LLM
это означает, что демонстрация проходит и на машине без установленной модели:
ответы помечаются `degraded=true`. Подробности — `docs/06-ai.md`.

## 6. Задел, НЕ подключённый в MVP (честно)

Эти компоненты обсуждались в архитектуре, но в коде MVP не используются —
в `requirements.txt` их нет намеренно, чтобы сборка отражала реальность:

| Компонент | Статус |
|---|---|
| `sentence-transformers` | Не установлен. Семантическое сопоставление реализовано через эмбеддинги Ollama (`qwen3-embedding`), поэтому отдельная библиотека не нужна |
| `pgvector` | Расширение доступно в образе БД, но векторы не хранятся: они считаются на лету. Кэш векторов — следующий шаг |
| Jinja2 | Не нужен: PDF-профиль собирается напрямую средствами reportlab |
| Redis-клиент, APScheduler | Удалены из зависимостей: регулярные короткие задания реализованы как API-ресурс (выдача/приём), отложенных задач в MVP нет. Сервис Redis поднят в compose как задел |
| Прокторинг | Только интерфейс-заглушка: по ТЗ не требуется для MVP |
